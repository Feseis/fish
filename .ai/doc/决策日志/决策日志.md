# 决策日志

状态：有效（产出物，只追加不回改）
用途：记录定型决策与踩坑，按 `D-xxx` 检索，不按时间顺序通读。
更新时间：2026-11-02

每条只写三要素：问题 / 决定 / 原因。

## D-001 失败响应使用 ProblemDetail，不引入 Result 壳

问题：接口失败时返回什么结构。
决定：成功返回裸 DTO；失败返回 RFC 9457 `ProblemDetail`，HTTP 状态由 `ErrorCode` 决定，自定义属性挂 `code`、`timestamp`。
原因：避免 HTTP 状态与 body 业务码重复表达；网关、日志、前端都能按标准结构直接识别。

## D-002 密码使用 BCrypt 哈希

问题：密码如何存储。
决定：`auth_password.password_hash` 存 BCrypt 哈希，`hash_algo` 记录算法。
原因：不可逆、自带盐，库泄露后无法还原明文。

## D-003 手机号作为唯一登录标识

问题：用账号名还是手机号登录。
决定：`auth_account.phone` 唯一，登录只接受手机号。
原因：减少一套账号命名规则，注册即验证手机号归属。

## D-004 角色拆成关联表，永久授予

问题：一个账号可以有多个角色，且后续可能扩展。
决定：`auth_role` 字典 + `auth_account_role` 多对多，无有效期字段。
原因：单列无法表达多角色；永久授予避免引入授权时效逻辑。

## D-005 一次登录一行会话

问题：会话如何建模。
决定：`auth_session` 每次登录插入一行，`session_id` 为服务端会话标识，记录 `pwd_version` 快照与过期时间。
原因：多设备天然分离，可按会话单独失效，不必按账号整体踢下线。

## D-006 refresh token 只存哈希

问题：长期令牌在库中怎么存。
决定：只存 `SHA-256(refresh_token)`，原值仅发给客户端。
原因：库泄露时无法直接冒用长期令牌；哈希不可逆且比 BCrypt 快，适合高频校验。

## D-007 短期令牌放 Redis

问题：短期令牌校验如何做到低延迟。
决定：短期令牌存 Redis 并设 TTL，到期后用 refresh 换新。
原因：避免每次请求查库；TTL 天然实现无感续签。

## D-008 环境变量由 spring.config.import 加载

问题：`a_run_env/auth.env` 怎么进入 Spring 环境。
决定：`spring.config.import: optional:file:../a_run_env/auth.env[.properties]`，用扩展名提示按 properties 解析。
原因：Boot 不原生读取 `.env`；`KEY=VALUE` 语法与 properties 兼容，无需重命名或依赖 IDE 插件。

## D-009 异常包命名为 exp

问题：`@RestControllerAdvice` 与业务异常放哪个包。
决定：`me.feseis.fish.auth.exp`。
原因：项目所有者指定；功能上等价于 exception，不额外抽象。

## D-010 会话设备信息暂不做

问题：是否需要区分登录设备。
决定：当前 `auth_session` 不存 `client_type`、`device_id`、`device_name`。
原因：先收敛认证主链路；后续需要「在线设备列表」「按设备踢下线」时再补，见待办 `F-01`。

## D-011 文档按职能分层

问题：项目文档如何组织才能控制上下文用量。
决定：`规范/`、`决策日志/`、`待办/`、`搁置/`、`接口契约/`、`操作手册/`、`草稿/`、`建库/` 分层；每份文件头部标注状态、用途、更新时间；AGENTS.md 只放文档地图。
原因：一个文件只回答一个问题，AI 按需加载；单点事实避免同一结论散落多处。

## D-012 仓库忽略策略：env 不入库，.idea 共享

问题：首次推送 GitHub 前，哪些本地文件应排除、哪些应保留。
决定：`a_run_env/*.env` 忽略，只提交模板 `a_run_env_example/auth.env`；`.idea/` 不全量忽略，`runConfigurations/`、`gradle.xml`、`vcs.xml` 等团队配置入库，本机文件由 `.idea/.gitignore` 排除；安卓构建产物由 `app/.gitignore` 的 `/build` 兜底，另补 `app/.cxx/`、`app/release/`。
原因：env 含数据库密码，推送后需轮换，提前拦住成本最低；`.idea` 共享配置体积小、能让成员开箱即用，而 `workspace.xml` 之类天然易冲突。

## D-013 环境文件统一按仓库根解析

问题：`spring.config.import: optional:file:../a_run_env/auth.env[.properties]` 在 IDE 直接运行时找不到文件，`optional:` 静默跳过，启动报 `AUTH_DB_URL` 占位符未解析（`Driver com.mysql.cj.jdbc.Driver claims to not accept jdbcUrl, ${AUTH_DB_URL}`）。
决定：以仓库根为唯一约定 cwd。`application.yml` 改为 `optional:file:./a_run_env/auth.env[.properties]`；`auth-server8081/build.gradle.kts` 的 `bootRun` 固定 `workingDir = rootProject.projectDir`；IDE 运行配置 Working directory 设为 `$PROJECT_DIR$`。
原因：`file:` 相对路径按进程 cwd 解析，原写法只在本机 cwd 恰为模块目录时成立；统一到仓库根后 Gradle 与 IDE 两种启动方式行为一致。曾被放弃的方案：保留 `../` 并要求 cwd 为模块目录（IDE 默认值不可控），以及写成绝对路径（不可移植）。

## D-014 安卓登录页首版为纯前端占位

问题：登录接口未实现时，安卓端登录页如何落地。
决定：启动页 `MainActivity` 仅保留空白背景与一个「去登录」按钮，显式跳转 `LoginActivity`；登录页用 `MaterialButtonToggleGroup` 提供密码/验证码两种模式，只做本地校验并 Toast 提示，不发起网络请求。
原因：`/auth/login` 仍规划中，先固定页面结构与入口；后续把本地校验替换为真实请求即可，不返工页面。

## D-015 登录响应统一，短信错误码沿用库表词表

问题：密码登录与验证码登录是否各自定义响应体、短信失败如何编码。
决定：两种登录共用 `LoginResponse`，`bean/dto/login` 只保留 `LoginOnPasswordRequest`、`LoginOnPhoneOnlyRequest`、`LoginResponse` 三个文件；新增错误码 `SMS_WRONG`、`SMS_EXPIRED`；发送验证码时未注册手机号复用 `NO_ACCOUNT`，不自动建号，由前端引导注册。
原因：响应字段完全一致，双份 DTO 只会带来维护分叉；两个短信错误码与 `auth_login_log.fail_reason` 既有注释词表一致，无需迁移脚本；不自动建号避免未完成注册流程就产生脏账号。

## D-016 App 图标直接使用 fish-logo 原图

问题：`fish-logo.png`（1254×1254、RGB 无 alpha、白底）如何做成启动器图标，是否裁掉白边、是否按图形本体对齐。
决定：不裁图，整张原图保留白边；自适应图标前景按 108dp 画布的 70%（75.6dp）居中贴入，白底与图标背景同色（`#FFFFFF`），按 mdpi~xxxhdpi 预烘焙 108/162/216/324/432 px 位图；不做非白像素外接框对齐，直接用整图几何中心。旧版图标（API < 26）覆盖原 webp：方形铺满、圆形按整图加圆形蒙版。移除 `<monochrome>` 层。
原因：原图图形本体实测只占高度 62.7%（宽 95.6%），按 70% 画布后本体约 47.4dp×72.3dp，符合安全区高度要求；`<monochrome>` 需要单色 alpha 蒙版，白底位图会渲染成实心方块，去掉后 Android 13 主题图标回退为原彩色图标。

## D-017 认证页采用浅色渐变 + 白色卡片，主题固定 Light

问题：登录页视觉单薄、缺少注册入口，且 DayNight 主题在深色模式下会让白卡片上的输入框文字不可读。
决定：登录/注册/首页统一为 `bg_auth_background` 渐变（`fish_bg_top`→`fish_bg_bottom`）+ 圆角 24dp 白色 `MaterialCardView`；新增 `RegisterActivity`（手机号、验证码、密码、确认密码，注册成功自动登录跳首页）；`Base.Theme.Fish` 在 `values/` 与 `values-night/` 都改为 `Theme.Material3.Light.NoActionBar`；文案颜色改用显式色值 `fish_text_primary` / `fish_text_secondary`。
原因：页面主色为浅色品牌底，只有固定 Light 才能保证输入框与文字对比度；注册与登录共用同一视觉骨架，减少后续维护分歧。
