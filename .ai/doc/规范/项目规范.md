# 项目规范

状态：有效（产出物）
用途：稳定约束。写代码前读；变更约束时写。
更新时间：2026-11-09

## 1 项目定位与模块

- fish：快递系统毕业设计（飞鱼速递）。
- `app`：Android 客户端，applicationId `me.feseis.fish`（高德 Key 按此包名 + SHA1 鉴权），Java 包名与 namespace 仍为 `com.feseis.fish`。
- `server8081-auth`：独立认证服务，只负责账号、登录、会话、角色与用户基础资料，不承载寄件/物流业务。
- `server8082-logistics`：物流业务服务，库 `fish_logistics`。
- `server8083-payment`：支付服务，库 `fish_payment`。
- `server8084-sms`：短信服务，库 `fish_sms`。
- `contract`：纯 Java 跨端协议常量模块，被 `app` 与四个后端服务依赖；不含 Spring、Android、Jackson、Jakarta 依赖。
- `common`：目录保留，已从 `settings.gradle.kts` 移除，当前不参与构建。

## 2 技术栈

- Java 21；Spring Boot 4.1.2；Gradle 8.14.3（仓库自带 wrapper）。
- 持久层 MyBatis（`mybatis-spring-boot-starter` 4.1.0），表结构由 Flyway 管理。
- MySQL 四库：`fish_auth`（认证）、`fish_logistics`（物流）、`fish_payment`（支付）、`fish_sms`（短信）；Redis 存放认证令牌，物流侧预留计费缓存。
- Boot 4 已模块化：Flyway 自动配置在独立的 `spring-boot-flyway` 依赖中，不再随 `spring-boot-autoconfigure` 提供。
- 密码哈希只使用 `spring-security-crypto` 的 `BCryptPasswordEncoder`，不引入整套 Spring Security。

## 3 认证模型

- 手机号是唯一登录标识，`auth_account.phone` 唯一。
- 角色多对多：`auth_account_role`，授予后长期有效、无有效期字段；离职时撤销，不是永久不可撤销。
- 用户基础资料 1:1 存 `auth_user_profile`（`auth_account_id` 唯一），姓名等业务展示统一以此为权威，业务库只存当前态快照；该表在 `fish_auth`，注册时同事务建空行，结构见 `草稿/auth扩展草稿.md`。
- 员工权限角色固定为 `auth_role_id=2`（显示名「物流员工」），不另设「员工」角色；岗位差异由业务库 `staff_role` 表达。实名认证已搁置，不设 `verified` 字段。
- 密码 1:1 存 `auth_password`；BCrypt 不可逆；`pwd_version` 改密时递增，用于让旧会话失效。
- 一次登录一行 `auth_session`；refresh token 原值只发给客户端，库中只存 SHA-256；状态 1 活跃 / 2 登出 / 3 被踢 / 4 过期。
- 双令牌分工：短期令牌放 Redis、可续签；refresh 只用于换新短期令牌（接口尚未实现）。

## 4 接口风格

- 成功：直接返回 DTO，HTTP 200，不包壳。
- 失败：RFC 9457 `ProblemDetail`，`Content-Type: application/problem+json`；HTTP 状态由 `ErrorCode` 决定，自定义属性挂 `code`、`timestamp`。
- `code` 取 `ErrorCode.name()`，与 `auth_login_log.fail_reason` 同一词表，改一处必须同步另一处。
- 禁止重新引入 `Result` 或 code-msg-data 统一壳（D-001）。
- 异常类型与全局处理只放在 `me.feseis.fish.auth.exp`；`@ExceptionHandler` 覆盖不到 Filter、容器层与异步线程的异常，需单独处理。

## 5 路径与包结构

- 服务前缀：auth `/auth`（健康检查 `/auth/health/**`）、logistics `/logistics`。
- 类级 `@RequestMapping` 写完整前缀段，方法级只写相对段，禁止重复前缀。
- 包职责（每个服务模块统一）：

| 包 | 职责 | 禁止 |
| --- | --- | --- |
| `controller` | 参数接收、校验注解、组装响应 | 写业务规则、直接调 mapper |
| `service` | 业务编排与领域规则；类名以 `Service` 结尾 | 发 HTTP 请求、拼 SQL、放无状态工具类 |
| `support` | 跨多个 Service 复用的无状态支撑：单号生成、状态守卫、权限守卫、费用关系推导 | 持有事务、编排业务流程、依赖 `client` |
| `routing` | 单一子域的自洽包：算法 + 快照 + 校验 + 启动钩子 | 混入其他子域职责 |
| `client` | 外部服务调用封装（高德、auth、支付、短信） | 写业务分支、读写本库 |
| `client/model` | 第三方渠道的返回结构 | 直接作为对外响应返回 |
| `config` | `@Configuration` 类、`properties/` 配置属性、`interceptor/` 请求链组件 | 放业务编排、外部调用、持久化 |
| `config/interceptor` | `HandlerInterceptor` 等请求链组件 | 放 `@Configuration`、业务逻辑 |
| `mapper` | MyBatis 接口；`mapper/model` 放查询行对象 | 写业务判断 |
| `vo` | 对外的入参/出参对象（App / 前端），按领域分子包 | 服务间 DTO、持久化逻辑 |
| `exp` | `ErrorCode`、`BizException`、`GlobalExceptionHandler` | 放业务代码 |

- 服务间 DTO 放独立 `xxx-api` 模块（现为 `auth-api`、`payment-api`、`sms-api`）：只放 DTO、路径常量、码值枚举；依赖仅 `compileOnly jakarta.validation-api`；禁止依赖 Spring、MyBatis 或任一服务模块。
- 依赖方向：消费方 → 提供方 `xxx-api`；提供方 `server` 使用同一份 DTO；禁止反向与跨服务互相引用。
- 命名：服务间 `XxxReqDTO` / `XxxRespDTO`；对外 `XxxReqVO` / `XxxRespVO`；持久化 `XxxRow`。服务模块内不再建 `dto` 包。
- 路径：对外接口不带 `internal`；服务间接口一律 `/xxx/internal/**`，便于后续挂内部令牌拦截。
- 三方渠道结构放 `client/model`，由 `service` 映射成 `vo`，禁止 `client` 直接返回 `vo`。

- 归属判定：类名以 `Service` 结尾且编排两个以上组件 → `service`；单号生成、守卫、纯计算等无状态复用件 → `support`；一个子域自带算法/快照/校验/启动钩子 → 独立子域包（现仅 `routing`）。新增子域包须先改本表。
- `contract` 只放跨端协议常量、枚举与无注解纯数据；不得引入 Spring、Android、Jackson、Jakarta 或任何 HTTP 客户端。
- 异常类型与全局处理只放在各服务的 `exp` 包；`@ExceptionHandler` 覆盖不到 Filter、容器层与异步线程的异常，需单独处理。

## 6 配置与环境

- 端口与身份：`server8081-auth` 8081/`auth-server`，`server8082-logistics` 8082/`logistics-server`，`server8083-payment` 8083/`payment-server`，`server8084-sms` 8084/`sms-server`。
- 环境变量来自 `a_run_env/<服务>.env`（`auth.env`、`logistics.env`、`payment.env`、`sms.env`），由 `spring.config.import: optional:file:./a_run_env/<服务>.env[.properties]` 加载；`file:` 相对路径按**当前工作目录**解析，因此 cwd 必须是仓库根：各模块 `build.gradle.kts` 的 `bootRun` 固定 `workingDir = rootProject.projectDir`，IDE 运行配置的 Working directory 也必须设为仓库根。
- auth 必需键：`AUTH_DB_URL`、`AUTH_DB_USERNAME`、`AUTH_DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`；其余服务按 `<服务>_DB_URL` 等前缀区分，详见各模块 `application.yml`。
- Flyway `baseline-on-migrate=true`，脚本位于各模块 `src/main/resources/db/migration`。

## 7 数据库与迁移

- 建库脚本 `.ai/doc/建库/建库.sql` 只建库；表结构全部由 Flyway 管理。
- 主键命名：主键 = 表名 + `_id`，跨表引用用全名。例如 `auth_account_id`、`logistics_site_id`，不用 `account_id`、`site_id` 这类脱离表名的缩写。既有表由 `V3__rename_auth_columns.sql` 改名，不设豁免。
- 跨表码值统一词表：`biz_type` = `1运单 2运单取消单 3员工入职申请单 4员工离职 5退回运费`；服务码 = `1认证 2物流 3支付 4短信`。不允许各表另立同名列词表。
- 字段长度与类型：人名字段 `VARCHAR(32)`，操作主体名称 `VARCHAR(64)`；码值列 `TINYINT UNSIGNED`，状态列 `TINYINT`。
- 字符集 `utf8mb4`；参与关联的字符列必须显式写 `COLLATE utf8mb4_general_ci`，否则 MySQL 8 取默认的 `utf8mb4_0900_ai_ci`，跨表 join 报 1267。
- 迁移失败：修脚本后 `flyway repair` 再 `migrate`，禁止手改 `flyway_schema_history`。

## 8 Redis 键设计（登录未实现，规划中）

- 所有键带 `auth:` 前缀，格式 `auth:{用途}:{标识}`。
- 一律设置 TTL，禁止永不过期的键。
- 短期令牌键规划为 `auth:st:{token}`，值含会话标识与 `account_id`，TTL 与短期令牌一致。
- 令牌原值不得进入键名或日志；必须落键时用 SHA-256 派生。
