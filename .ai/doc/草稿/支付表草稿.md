# 支付表草稿

状态：草稿（不长期维护）
用途：支付服务表结构讨论稿，含支付单、退款单、催付提醒、事件投递；定稿后分流至决策日志与待办。
更新时间：2026-11-06

## 已裁决口径

### 定位

- 支付服务独立微服务，库 `fish_payment`，不只服务运单，用 `biz_type + biz_id` 多态关联业务。
- `biz_type` 使用全库统一词表：`1运单 2运单取消单 3员工入职申请单 4员工离职 5退回运费`；本服务只处理 1 与 5。
- 服务间调用统一服务码：`1认证 2物流 3支付 4短信`。
- 金额单位元，`DECIMAL(10,2)`；`biz_type=1` 时直接取 `waybill.total_amount`，`biz_type=5` 时按 `price_rule` 重算退回运费。

### 支付单

- 一个业务可有多条支付单（失败重试），但**只能有一条成功**，由 `paid_biz_key` 唯一键保证。
- 状态：`1待支付 2已支付 3支付失败 4已关闭 5已全额退款 6已超时待介入`。
- 支付成功判定只有两个来源：渠道异步回调、主动查单。前端上报一律不信。
- 结算用条件更新抢唯一赢家：`UPDATE ... WHERE payment_no=? AND status IN (1,3,4,6)`，影响行数为 1 才继续。
- `status=4 已关闭` 只是本地超时展示，渠道侧可能仍放行支付：迟到回调允许从 4 进入 2，并在 `pay_remark` 记「关闭后迟到支付」。渠道下单参数同时设 `timeout_express=30m`，让渠道侧也拒绝超时支付。
- `payment_no` 纯字母数字，直接作为渠道 `out_trade_no`，避免渠道字符集限制。
- 超时判失败不阻止迟到成功：条件更新允许从 6 进入 2。
- 复活原单：到付超时人工介入走 `6→1`（`remind_count=0`、`expire_at=now()+48h`、重新生成 `pay_token`）；退回运费欠费结清走 `4→1`（`expire_at=now()+24h`、`closed_at=NULL`）。两者都不新建支付单，避免旧单永远停在 4/6 导致欠费拦截无法解除。
- 支付成功撞 `uk_paid_biz`：说明该业务已有成功支付单，本单不写 `paid_biz_key`，置 `status=2`、`pay_remark='重复支付，待人工退款'`；渠道已收款必须留账。

### 匿名付款

- 到付时收件人可能没有 App 账号，`payer_type=2`，`payer_account_id` 为 NULL。
- 匿名付款靠一次性令牌：`pay_token` 随机 32 字节，有效期与 `expire_at` 一致（到付 48 小时），支付成功或过期后置 NULL。
- 令牌只授权「付这一单」，不携带身份，不能查询其他运单。
- 二维码由快递员 App 展示；同一条链接可短信发送到 `waybill.receiver_phone`。
- 到付单在运单进入 `4派送中` 时才创建，48 小时从开始派送算，不在下单时建单。
- 寄付单在下单成功后立即创建，有效期 30 分钟；到付单在进入 `4派送中` 时创建，有效期 48 小时。
- 到付单必须 `status=2` 才允许签收；未支付只能拒收并转退回。

### 超时的两种含义

- `expire_at` 是**单次支付凭证的有效期**，也是 `pay_token` 的有效期：寄付 App 支付取 30 分钟，到付匿名支付取 48 小时。两者语义相同，不再单列令牌过期时间。
- `status=6 已超时待介入` 只用于到付：48 小时催付期满后进入，此时 `pay_token` 置 NULL。
- 寄付单过期直接置 `4 已关闭`，不进入 6。

### 催付与报备

- 到付单每 8 小时提醒一次，最多 6 次（第 8/16/24/32/40/48 小时）。
- 建单时 `next_remind_at = created_at + 8h`；寄付单该列为 NULL。
- 并发防重不靠唯一索引，靠 `remind_count` 乐观锁：`UPDATE payment SET remind_count=remind_count+1, next_remind_at=? WHERE payment_id=? AND remind_count=? AND next_remind_at<=NOW()`，影响行数为 1 才发短信。发送失败不回滚计数，下一次定时任务按 `next_remind_at` 继续，不会重复发同一轮。
- 第 6 次提醒文案不带支付链接（此时 `expire_at` 已到），改为提示联系快递员；随后 `status=6`、`pay_token=NULL`、`next_remind_at=NULL`，写 `payment_outbox` 报备事件。
- 物流服务收到报备后：写 `waybill_exception`（原因码 8 到付超时未付，系统标记）→ 运单置 `7异常` → 写轨迹。

### 退款

- 运单进入 `6已取消` 或 `8退回中` 时，物流服务在同一事务写 `event_outbox.event_type=3 业务终止`，支付服务据此结算该运单的支付单。
- 消费逻辑：按 `waybill_id` 查 `biz_type=1` 的支付单；`status IN (1,3,6)` 置 `4已关闭`；`status=2` 创建全额退款；无支付单直接返回成功。
- `refund_source` 由事件 `biz_type` 映射：`2运单取消单 → 1运单取消`，`1运单 → 4运单退回`（拒收、退回）。
- 当前策略为**全额原路退**：`refund.amount` 恒等于 `payment.amount`，代码校验，表结构保留金额列。
- 退款成功同一事务更新 `refund.status=2`、`refund.refunded_at`、`payment.status=5`。
- `refund.refund_source` 是触发来源枚举，不是业务对象词表；业务对象通过 `payment.biz_type + biz_id` 反查。取值：`1运单取消 2异常处理 3人工 4运单退回`。
- **防重复退款**：`refund` 对 `payment_id` 建唯一键。当前全额策略下，一个支付单最多一条退款单；创建时撞键直接复用已有记录。未来支持部分退款时，把唯一键改为 `(payment_id, refund_no)`。

### 退回运费

- 退回运输由寄出者二次付费，`biz_type=5`、`biz_id=waybill_return_id`，与原运单的 `1:waybill_id` 不冲突。
- 付款人固定为寄出者：`payer_type=1`、`payer_account_id=waybill.auth_account_id`、`payer_phone` 取寄件人手机号快照。
- 金额按当前 `price_rule` 重算运费，不含保价费；不取原运单的 `freight_amount` 快照，因为规则可能已改价。
- 建单时机：物流服务创建 `waybill_return` 时调用支付服务。
- `expire_at` 取 48 小时，不是寄付的 30 分钟。
- **不阻塞退回运输**：未支付只标记欠费并短信催付，货照常退回；欠费处置见下节。
- 原支付单照常全额退款（`refund_source=4 运单退回`），两笔资金互不影响。
- 欠费催收用 `payment_reminder.remind_type=2` 留痕：第 1、3、7 天各一条，以 `payment.closed_at` 为基准计算，发送前按 `(payment_id, remind_type=2, remind_no)` 判重，且只统计 `created_at >= payment.closed_at` 的记录（复活后重新计周期）。

### 退回运费欠费处置

- 支付单过 `expire_at` 仍未支付时置 `4已关闭`，即视为欠费；不阻塞退回运输。
- 催收节奏：第 1、3、7 天各发一条短信，模板 `ARREARS_REMIND`；用 `payment_reminder.remind_type=2` 留痕，以 `payment.closed_at` 为基准按天计算，发送前按 `(payment_id, remind_type=2, remind_no)` 判重，且只统计 `created_at >= payment.closed_at` 的记录。
- **硬拦截**：下单前查该账号是否存在未结清的 `biz_type=5` 支付单（`status IN (3,4)`），有则拒绝下单；支付服务调用失败按 fail-open 处理，不阻断下单，记告警。
- **结清入口**：`GET /payment/arrears?authAccountId=...` 查询未结清账单，`POST /payment/arrears/{paymentId}/pay` 把原单 `4→1`（顺延 24 小时、清空 `closed_at`）并返回支付参数；不新建支付单，避免旧单永远为 4。
- 欠费不新增表，状态从 `payment` 推导。

### 跨服务一致性

- 支付服务对物流服务的通知走 `payment_outbox`，与业务写入同一本地事务。
- `payment_outbox` 只保留两个事件：`1 到付超时报备`、`2 退款完成`。支付成功与支付失败不投递——运单不存支付状态，物流侧无动作可做。
- 物流服务处理事件必须幂等：按 `(event_type, payment_id)` 或 `(event_type, refund_id)` 去重，重复投递不重复写 `waybill_exception`。

## payment

```sql
CREATE TABLE payment (
  payment_id       CHAR(36)      NOT NULL COMMENT '支付单主键 UUID',
  payment_no       VARCHAR(32)   NOT NULL COMMENT '对外支付单号：P+yyMMdd+8位日序号，纯字母数字，直接作渠道 out_trade_no',
  biz_type         TINYINT UNSIGNED NOT NULL COMMENT '业务类型（全库统一词表）：1运单 5退回运费',
  biz_id           CHAR(36)      NOT NULL COMMENT '业务主键：biz_type=1 时为 waybill.waybill_id；biz_type=5 时为 waybill_return.waybill_return_id',

  payer_type       TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '付款人类型：1账号 2匿名（扫码链接）',
  payer_account_id CHAR(36)      NULL     COMMENT '付款账号 → auth_account.auth_account_id；payer_type=2 时为 NULL',
  payer_phone      VARCHAR(20)   NULL     COMMENT '付款人手机号快照；匿名时取运单收件人手机号',

  amount           DECIMAL(10,2) NOT NULL COMMENT '应付金额，单位元，取运单下单快照',
  pay_channel      TINYINT UNSIGNED NOT NULL COMMENT '1模拟支付 2支付宝沙箱 3微信',
  status           TINYINT       NOT NULL DEFAULT 1 COMMENT '1待支付 2已支付 3支付失败 4已关闭 5已全额退款 6已超时待介入；4→1 仅限 biz_type=5 欠费结清，6→1 仅限到付人工介入',
  channel_trade_no VARCHAR(64)   NULL     COMMENT '渠道交易号；模拟支付为空',
  paid_biz_key     VARCHAR(80)   NULL     COMMENT '成功占位：成功时填 biz_type:biz_id；唯一键保证同一业务只有一条成功支付；重复支付不填此列',
  pay_remark       VARCHAR(255)  NULL     COMMENT '失败原因或渠道返回信息；关闭后迟到支付记「关闭后迟到支付」',

  pay_token        VARCHAR(64)   NULL     COMMENT '匿名付款令牌，32 字节随机串；成功或过期后置 NULL',
  remind_count     TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '已发送催付提醒次数，上限 6；同时是定时任务的乐观锁版本号',
  next_remind_at   DATETIME      NULL     COMMENT '下次催付时间；已支付、已关闭或停止提醒为 NULL',

  expire_at        DATETIME      NOT NULL COMMENT '单次支付凭证有效期，也是 pay_token 有效期：寄付 30 分钟，到付匿名 48 小时；复活原单时按规则顺延',
  paid_at          DATETIME      NULL     COMMENT '支付成功时间',
  closed_at        DATETIME      NULL     COMMENT '关闭时间；欠费结清复活原单时清空',
  created_at       DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at       DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (payment_id),
  UNIQUE KEY uk_payment_no (payment_no),
  UNIQUE KEY uk_channel_trade (pay_channel, channel_trade_no),
  UNIQUE KEY uk_paid_biz (paid_biz_key),
  UNIQUE KEY uk_pay_token (pay_token),
  KEY idx_biz (biz_type, biz_id),
  KEY idx_status_expire (status, expire_at),
  KEY idx_remind (status, next_remind_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='支付单表';
```

## refund

```sql
CREATE TABLE refund (
  refund_id         CHAR(36)      NOT NULL COMMENT '退款单主键 UUID',
  refund_no         VARCHAR(32)   NOT NULL COMMENT '对外退款单号，唯一',
  payment_id        CHAR(36)      NOT NULL COMMENT '→ payment.payment_id；退款挂在支付单上',
  amount            DECIMAL(10,2) NOT NULL COMMENT '退款金额；当前策略恒等于支付金额',
  refund_source     TINYINT UNSIGNED NOT NULL COMMENT '触发来源：1运单取消 2异常处理 3人工 4运单退回；业务对象经 payment 反查',
  reason            VARCHAR(128)  NULL     COMMENT '退款原因，业务方传入文本',
  status            TINYINT       NOT NULL DEFAULT 1 COMMENT '1待退款 2已退款 3退款失败',
  channel_refund_no VARCHAR(64)   NULL     COMMENT '渠道退款流水号，唯一',
  refunded_at       DATETIME      NULL     COMMENT '退款成功时间',
  refund_remark     VARCHAR(255)  NULL     COMMENT '失败原因',
  created_at        DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (refund_id),
  UNIQUE KEY uk_refund_no (refund_no),
  UNIQUE KEY uk_payment (payment_id),
  UNIQUE KEY uk_channel_refund (channel_refund_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='退款单表';
```

`uk_payment` 是当前全额退款策略下的防重核心：一个支付单最多一条退款单。未来支持部分退款时改为 `(payment_id, refund_no)`。

## payment_reminder

```sql
CREATE TABLE payment_reminder (
  payment_reminder_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '提醒记录主键，自增',
  payment_id          CHAR(36)        NOT NULL COMMENT '→ payment.payment_id',
  remind_type         TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1到付催付 2退回运费欠费催收',
  remind_no           TINYINT UNSIGNED NOT NULL COMMENT '第几次提醒：到付 1..6，欠费 1..3（第1/3/7天）',
  send_channel        TINYINT UNSIGNED NOT NULL COMMENT '1短信',
  target_phone        VARCHAR(20)     NOT NULL COMMENT '接收手机号，发送时快照',
  result              TINYINT UNSIGNED NOT NULL COMMENT '1成功 2失败',
  fail_reason         VARCHAR(128)    NULL     COMMENT '失败原因',
  created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发送时间，即时发送无需另设 sent_at',

  PRIMARY KEY (payment_reminder_id),
  KEY idx_payment_remind (payment_id, remind_type, remind_no),
  KEY idx_payment_time (payment_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='支付催付提醒记录表（到付/欠费）';
```

到付并发防重由 `payment.remind_count` 乐观锁承担，本表不设唯一键：发送失败也要留痕，且下一次定时任务允许重试同一轮。欠费催收按 `(payment_id, remind_type=2, remind_no)` 判重。

## payment_outbox

```sql
CREATE TABLE payment_outbox (
  payment_outbox_id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '事件主键，自增',
  target_service    TINYINT UNSIGNED NOT NULL COMMENT '目标服务：2物流；服务码全库统一',
  event_type        TINYINT UNSIGNED NOT NULL COMMENT '本表独立事件词表：1到付超时报备 2退款完成；不与 event_outbox 共用',
  biz_type          TINYINT UNSIGNED NOT NULL COMMENT '业务类型（全库统一词表）：1运单 5退回运费',
  biz_id            CHAR(36)        NOT NULL COMMENT '业务主键',
  payment_id        CHAR(36)        NULL     COMMENT '关联支付单',
  refund_id         CHAR(36)        NULL     COMMENT '关联退款单',
  status            TINYINT         NOT NULL DEFAULT 1 COMMENT '1待投递 2已投递 3待重试 4已放弃',
  retry_count       TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '已重试次数',
  next_retry_at     DATETIME        NULL     COMMENT '下次重试时间；待投递为 NULL',
  last_error        VARCHAR(255)    NULL     COMMENT '最近一次失败原因',
  created_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (payment_outbox_id),
  KEY idx_status_next (status, next_retry_at),
  KEY idx_biz (biz_type, biz_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='支付服务事件投递表（Outbox）';
```

## 支付成功后的动作

```
① UPDATE payment SET status=2, paid_at=now(), channel_trade_no=?, paid_biz_key=CONCAT(biz_type,':',biz_id)
   WHERE payment_no=? AND status IN (1,3,4,6)
   影响行数 = 0 → 已是终态，按幂等直接返回成功
② 不写 payment_outbox
COMMIT
```

支付成功不驱动物流侧任何状态变更：寄付成功后运单仍是 `1待揽收`，到付成功后运单仍在 `4派送中`。运单不存支付快照，需要展示支付状态时由调用方按 `biz_type=1 + waybill_id` 查支付服务。

## 到付超时报备

```
① UPDATE payment SET status=6, pay_token=NULL, next_remind_at=NULL
   WHERE payment_id=? AND status=1 AND remind_count>=6
② INSERT payment_outbox (target_service=2, event_type=1, biz_type=1, biz_id=waybill_id, payment_id=?)
COMMIT
```

物流服务收到后在同一事务写 `waybill_exception`（原因码 8）→ 运单置 `7异常` → 写轨迹。

## 业务终止消费

```
① 按 waybill_id 查 payment WHERE biz_type=1 AND biz_id=waybill_id
② status IN (1,3,6) → UPDATE status=4, closed_at=now()
③ status=2 → INSERT refund (payment_id, amount=payment.amount, refund_source=由事件 biz_type 映射)
   撞 uk_payment 直接复用已有退款单
④ 无支付单 → 直接返回成功
```

消费必须幂等：重复投递不会重复关单或重复退款；退款单存在即视为已完成。
