# 运单表草稿

状态：草稿（不长期维护）
用途：快递业务表结构讨论稿，含运单、轨迹、取消、异常、退回、审核、网点；定稿后分流至决策日志与待办。
更新时间：2026-11-06

## 已裁决口径

### 运单主表

- 一票一件：物品信息内联在 `waybill`，不拆 `waybill_item`。
- 状态用 `waybill.status` 单列枚举，历史变化交给轨迹表。
- `waybill_no` 规则：`FF` + `yyMMdd` + 6 位日序号，如 `FF251105000042`，长度 14，`VARCHAR(20)` 有余量。
- `item_category` 独立字典表，`waybill` 内联 `item_category_id`；`item_category` 是可选字典，保留 `enabled`。
- `auth_account_id` 跨库只存值，不建外键。
- 金额只存下单时算定的结果快照，不存计算过程。
- `delivered_at` 只写状态 5 的正常签收；退回签收不写此字段，退回时间见 `waybill_return.completed_at`。
- 取消原因与取消时间不落 `waybill`，移交取消业务表。
- 运单地址**内联快照**，不存 `geo_address_id`：运单是历史凭证，POI 名称或坐标变更不得改写已下单内容；`user_address` 与 `logistics_site` 才引用 `geo_address`。
- 金额快照口径：`waybill.total_amount` 是下单时算定的唯一金额来源；支付单的 `amount` 直接取该值，不重新计算。
- 计费依据见 `计费规则草稿.md`：按寄收 `adcode` 判定同城/省内/跨省，取对应 `price_rule` 与 `insurance_rule`；运单存金额与两个规则 ID，不存计算过程。
- `sender_adcode` / `receiver_adcode` 是计费与网点反查的前置字段，下单时必须非空；POI 必选保证了它们可从 `geo_address` 带入。

### 轨迹

- 五要素：which order / who / when / what / result，分别由 `waybill_id`、`operator_*`、`occurred_at`、`trace_action_id`、`status_after` 承担。
- `who` 用 `operator_type` + `operator_id` + `operator_name` 快照表达，不建统一操作员表；`operator_type` 枚举 `1系统 2物流人员 3网点 4用户`，系统事件 `operator_id=NULL`。
- 系统事件定义：由时间到期或阈值触发、无人按下按钮的状态变更。
- 轨迹只回答「发生了什么」，原因由取消/异常等业务表承载；轨迹不设自由文本与备注。
- 发生地点不单独存字段：网点事件用 `operator_id` 关联，物流人员事件用运单寄收地址，系统事件无地点。
- 「下单」不作轨迹首条，运单创建即起点；「退回」纳入动作与状态枚举。
- `trace_action` 是事实字典，不设 `enabled`。
- 主键遵循「表名 + `_id`」，日志表用 `BIGINT UNSIGNED` 自增，业务表用 `CHAR(36)` UUID。
- 名称类字段长度：人名统一 `VARCHAR(32)`；操作主体（可能是人名或网点名）统一 `VARCHAR(64)`。
- 码值列统一 `TINYINT UNSIGNED`，状态列统一 `TINYINT`。

### 取消与审核

- 一条运单可多轮申请取消，每轮一条 `waybill_cancel` 记录，`apply_round` 从 1 递增。
- 唯一键 `(waybill_id, apply_round)`；并发下取 `MAX(apply_round)+1`，撞键由唯一索引兜底重试。
- 「同一运单最多一条 `cancelled_at` 非空」由应用层保证，数据库无法用普通唯一索引表达。
- 取消申请只允许在状态 `1待揽收 / 2已揽收 / 3运输中 / 7异常` 发起；`4派送中` 走拒收或退回，终态不可发起。
- 取消原因用字典 `cancel_reason` + 可空备注；`cancel_reason` 是可选字典，保留 `enabled`。
- `approval` 为通用审核表，用 `biz_type` + `biz_id` 多态关联业务记录，无数据库外键，一致性由应用层保证。
- **审核指针单向**：只有 `approval.biz_type + biz_id`，业务表不存 `approval_id`；反查靠 `uk_biz (biz_type, biz_id)` 唯一索引点查。避免双向指针漂移。
- `biz_type` 使用全库统一词表：`1运单 2运单取消单 3员工入职申请单 4员工离职 5退回运费`。`approval` 只取 2 或 3。
- `biz_type=2` 时 `biz_id` 指向 `waybill_cancel.waybill_cancel_id`；`biz_type=3` 时指向 `staff_apply.staff_apply_id`；`biz_type=4` 时指向 `logistics_staff.logistics_staff_id`，仅 Outbox 使用；`biz_type=5` 时指向 `waybill_return.waybill_return_id`，仅支付单使用。
- `approval.status`：`1待审核 2通过 3驳回 4已撤回`。
- `waybill_cancel.operator_*` 与 `approval.apply_operator_*`、`cancel_remark` 与 `apply_remark` 分别为「执行事实」与「申请事实」，两者都保留，同一事务写入。
- 时间字段只保留一种语义：`created_at` 即「申请/发起/标记」时间，不再另设 `applied_at`、`initiated_at` 等恒等列。仅当业务时间可与入库时间分离时（如 `cancelled_at`、`completed_at`、`picked_at`、`delivered_at`）才单独设列。唯一例外是 `waybill_trace`：轨迹允许离线补录，`occurred_at` 记业务发生时间，`created_at` 记入库时间。
- 审核通过时同一事务内：按 `status_before` 计算目标状态（1/2 或异常来源 1/2 → 6；3 或异常来源 3/4/8 → 8），执行 `UPDATE waybill SET status=? WHERE waybill_id=? AND status=status_before`，影响行数为 1 才更新 `approval.status`、写 `waybill_cancel.cancelled_at`、写取消轨迹，并在进入 6/8 时写业务终止事件；影响行数为 0 说明申请后运单状态已变，整笔回滚，`approval` 置驳回并记「状态已变更」。
- 取消与货物位置联动：`1待揽收 / 2已揽收` 取消直接置 6；`3运输中` 取消不置 6，改为置 `8退回中` 并同一事务写一条 `waybill_return`（`return_reason=7 运单取消退回`），退款照常触发，退回签收后进 9。`7异常` 取消按最近一条 `waybill_exception.status_before` 分流：来源是 1/2 则置 6，来源是 3/4/8 则走 8。
- 运单进入 `6已取消` 或 `8退回中` 时，同一事务写一条 `event_outbox`（`event_type=3 业务终止`）：取消场景 `biz_type=2 + biz_id=waybill_cancel_id`，退回场景 `biz_type=1 + biz_id=waybill_id`，两种都填 `waybill_id`。支付服务据此关闭该运单下未支付的支付单，或对已支付单建全额退款。

### 异常与退回

- 轨迹只回答「发生了什么」，异常与退回的**原因**分别由 `waybill_exception`、`waybill_return` 承载。
- 异常与退回各自配一张可选字典：`exception_reason`、`return_reason`，均保留 `enabled`。
- 两张业务表都存 `operator_*` 三件套快照与 `status_before`，口径与 `waybill_cancel` 一致。
- 异常默认由现场人员标记；**允许系统标记的唯一场景**是到付超时报备（48 小时未支付），此时 `operator_type=1`、`operator_id=NULL`。
- 到付超时报备的完整动作在同一事务内：写 `waybill_exception`（原因码 8 到付超时未付）→ 运单置 `7 异常` → 写一条动作码 7 的轨迹。
- 退回发起前状态限 `3运输中 / 4派送中 / 7异常`；其中 `3运输中` 只由取消联动写入，不单独允许人工发起。退回签收时间落 `waybill_return.completed_at`，不再从轨迹反推。
- 退回运费由寄出者二次付费，`biz_type=5 + waybill_return_id` 独立建支付单；未支付不阻塞退回运输，细则见 `支付表草稿.md`。
- 从 `7异常` 跳出时必须结合该运单最近一条 `waybill_exception.status_before` 判定：来源是 1/2 只允许回 6（取消）或 3；来源是 3/4 允许回 3/4 或走 8；来源是 8 只允许回 8 或走 9。异常解除写动作码 13。
- 签收方式拆动作码而非加字段：`6本人签收 / 11他人代收 / 12驿站签收`，三者结果状态均为 5。

### 网点

- 网点、转运中心、驿站共一张 `logistics_site`，用 `site_type` 区分：`1营业网点 2转运中心 3驿站/自提点`。
- 层级用 `parent_logistics_site_id`：转运中心为 NULL，营业网点指向转运中心，驿站指向营业网点，形成「1 转运中心 : N 网点」。
- 地址复用 `geo_address`，本表只存 `detail_addr`，与 `user_address` 同构；建网点必须先有 `geo_address` 行。
- 不设营业时间字段，不冗余省市区/`adcode`/坐标列。
- `site_code` 唯一且不回收，停用后仍占用编码。
- 停用不删行，置 `enabled=0`；历史轨迹仍需渲染。
- `logistics_staff_id` 指向物流人员表 `logistics_staff`，待数据回填；`leader_name` 是**当前负责人姓名副本**，用于业务表独立展示，变更负责人时两列同一次写入。
- 姓名三层口径：auth 的 `auth_user_profile.real_name` 为权威；业务表当前态（`logistics_staff.staff_name`、`logistics_site.leader_name`）随改名更新；历史凭证（`waybill_trace.operator_name` 等）永不更新。
- `logistics_site_area` 只登记 `site_type=1` 营业网点；驿站是点状覆盖（按坐标算距离），转运中心无覆盖概念，二者都不进该表。
- 关系定为 1:N：一个营业网点覆盖多个区县，一个区县只归属一个营业网点，`adcode` 单列唯一；当前不做大城市分片。
- `waybill` 不加快照网点字段：实际作业网点已由轨迹 `operator_type=3` 留痕，归属网点属可推导的配置事实。
- 主键与跨表引用按 D-022 用全名：`logistics_site_id`、`logistics_site_area_id`、`logistics_staff_id`。

## waybill

```sql
CREATE TABLE waybill (
  waybill_id   CHAR(36)    NOT NULL COMMENT '运单主键，UUID',
  waybill_no   VARCHAR(20) NOT NULL COMMENT '对外单号：FF+yyMMdd+6位日序号，如 FF251105000042',
  auth_account_id   CHAR(36)    NOT NULL COMMENT '下单账号 → auth_account.auth_account_id；跨库只存值，不建外键',

  -- ===== 寄件人快照（不引用 user_address，防历史被改写）=====
  sender_name         VARCHAR(32)   NOT NULL COMMENT '寄件人姓名',
  sender_phone        VARCHAR(20)   NOT NULL COMMENT '寄件人手机号',
  sender_province     VARCHAR(32)   NOT NULL COMMENT '省',
  sender_city         VARCHAR(32)   NOT NULL COMMENT '市；直辖市以省填充',
  sender_district     VARCHAR(32)   NOT NULL COMMENT '区/县',
  sender_detail_addr  VARCHAR(200)  NOT NULL COMMENT '详细门牌，唯一可送达依据',
  sender_adcode       CHAR(6)       NOT NULL COMMENT '行政区划码；由 geo_address 带入，下单时必须非空',
  sender_poi_id       VARCHAR(64)   NOT NULL COMMENT '高德 POI ID；D-022 规定 POI 必选，故非空',
  sender_poi_name     VARCHAR(128)  NULL     COMMENT 'POI 名称，辅助',
  sender_lng          DECIMAL(10,6) NOT NULL COMMENT 'GCJ-02 经度；POI 必选故非空',
  sender_lat          DECIMAL(10,6) NOT NULL COMMENT 'GCJ-02 纬度；POI 必选故非空',

  -- ===== 收件人快照 =====
  receiver_name         VARCHAR(32)   NOT NULL COMMENT '收件人姓名',
  receiver_phone        VARCHAR(20)   NOT NULL COMMENT '收件人手机号',
  receiver_province     VARCHAR(32)   NOT NULL COMMENT '省',
  receiver_city         VARCHAR(32)   NOT NULL COMMENT '市；直辖市以省填充',
  receiver_district     VARCHAR(32)   NOT NULL COMMENT '区/县',
  receiver_detail_addr  VARCHAR(200)  NOT NULL COMMENT '详细门牌，唯一可送达依据',
  receiver_adcode       CHAR(6)       NOT NULL COMMENT '行政区划码；由 geo_address 带入，下单时必须非空',
  receiver_poi_id       VARCHAR(64)   NOT NULL COMMENT '高德 POI ID；D-022 规定 POI 必选，故非空',
  receiver_poi_name     VARCHAR(128)  NULL     COMMENT 'POI 名称，辅助',
  receiver_lng          DECIMAL(10,6) NOT NULL COMMENT 'GCJ-02 经度；POI 必选故非空',
  receiver_lat          DECIMAL(10,6) NOT NULL COMMENT 'GCJ-02 纬度；POI 必选故非空',

  -- ===== 物品（一票一件，直接内联）=====
  item_name         VARCHAR(64)      NOT NULL COMMENT '物品名称，用户填写',
  item_category_id  TINYINT UNSIGNED NULL     COMMENT '→ item_category.item_category_id；NULL 表示未分类',
  item_weight       DECIMAL(10,3)    NOT NULL COMMENT '下单时用户填写的计费重量 kg；不做体积重',
  declared_value    DECIMAL(10,2)    NULL     COMMENT '申报价值，用户可选填；NULL 表示未申报，不参与保价',

  -- ===== 金额（下单时算定的快照，不存计算过程）=====
  freight_amount    DECIMAL(10,2)  NOT NULL DEFAULT 0.00 COMMENT '运费',
  insured_fee       DECIMAL(10,2)  NOT NULL DEFAULT 0.00 COMMENT '保价费，未申报时为 0',
  total_amount      DECIMAL(10,2)  NOT NULL DEFAULT 0.00 COMMENT '应付总额 = 运费 + 保价费',
  price_rule_id     BIGINT UNSIGNED NULL    COMMENT '下单时使用的运费规则 → price_rule.price_rule_id；便于追溯费率',
  insurance_rule_id BIGINT UNSIGNED NULL    COMMENT '下单时使用的保价规则 → insurance_rule.insurance_rule_id；未申报保价时为 NULL',
  pay_method        TINYINT UNSIGNED NOT NULL COMMENT '1寄付 2到付；下单必选，决定支付单建单时机',

  -- ===== 状态（单列枚举，历史交给轨迹表）=====
  status  TINYINT NOT NULL DEFAULT 1 COMMENT '1待揽收 2已揽收 3运输中 4派送中 5已签收 6已取消 7异常 8退回中 9已退回',

  -- ===== 时间节点（中间节点由轨迹表推导；取消时间见取消表）=====
  picked_at     DATETIME NULL COMMENT '揽收时间',
  delivered_at  DATETIME NULL COMMENT '正常签收时间（状态5）；退回签收不写此字段，退回时间见 waybill_return.completed_at',
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '下单时间',
  updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  remark  VARCHAR(255) NULL COMMENT '用户备注',

  PRIMARY KEY (waybill_id),
  UNIQUE KEY uk_waybill_no (waybill_no),
  KEY idx_account_time (auth_account_id, created_at),
  KEY idx_status_time (status, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='运单主表';
```

## trace_action

```sql
CREATE TABLE trace_action (
  trace_action_id  TINYINT UNSIGNED NOT NULL COMMENT '动作码，固定枚举，非自增',
  action_name      VARCHAR(32)      NOT NULL COMMENT '动作名，如揽收/到达/派送/本人签收',
  PRIMARY KEY (trace_action_id),
  UNIQUE KEY uk_action_name (action_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='轨迹动作字典表';
```

动作码与结果状态对应：

| 码 | 动作 | 结果状态 |
| --- | --- | --- |
| 1 | 揽收 | 2 已揽收 |
| 2 | 到达网点/转运中心 | 3 运输中 |
| 3 | 离开网点/转运中心 | 3 运输中 |
| 4 | 派送中 | 4 派送中 |
| 5 | 投递失败 | 4 不变 |
| 6 | 本人签收 | 5 已签收 |
| 7 | 异常 | 7 异常 |
| 8 | 取消 | 6 已取消 |
| 9 | 退回 | 8 退回中 |
| 10 | 退回签收 | 9 已退回 |
| 11 | 他人代收 | 5 已签收 |
| 12 | 驿站签收 | 5 已签收 |
| 13 | 异常解除 | 恢复到异常前状态，实际值由 `status_after` 记录 |

码值 11、12 为追加，码值 13 为异常解除追加，历史码值不重编号。动作 2、3（到达/离开）的结果状态取决于运单所处阶段：正常运输时为 3，`8退回中` 的返程过站时仍为 8。

## waybill_trace

```sql
CREATE TABLE waybill_trace (
  waybill_trace_id  BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '轨迹主键，自增',
  waybill_id        CHAR(36)         NOT NULL COMMENT '→ waybill.waybill_id',
  operator_type     TINYINT UNSIGNED NOT NULL COMMENT '1系统 2物流人员 3网点 4用户',
  operator_id       CHAR(36)         NULL     COMMENT '操作主体ID；系统事件为 NULL',
  operator_name     VARCHAR(64)      NULL     COMMENT '操作者名称快照；系统事件为 NULL',
  trace_action_id   TINYINT UNSIGNED NOT NULL COMMENT '→ trace_action.trace_action_id，表达「在做什么」',
  status_after      TINYINT          NOT NULL COMMENT '事件后运单状态；未改变状态的事件填当前状态',
  occurred_at       DATETIME         NOT NULL COMMENT '业务发生时间',
  created_at        DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '入库时间',
  PRIMARY KEY (waybill_trace_id),
  KEY idx_waybill_time (waybill_id, occurred_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='运单轨迹表（append-only）';
```

## cancel_reason

```sql
CREATE TABLE cancel_reason (
  cancel_reason_id  TINYINT UNSIGNED NOT NULL COMMENT '原因码，固定枚举，非自增',
  reason_name       VARCHAR(32)      NOT NULL COMMENT '原因名，如「信息填写错误」',
  enabled           TINYINT          NOT NULL DEFAULT 1 COMMENT '1启用 0停用；取消页只展示启用项',
  PRIMARY KEY (cancel_reason_id),
  UNIQUE KEY uk_reason_name (reason_name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='取消原因字典表';
```

| 码 | 原因 | 典型发起方 |
| --- | --- | --- |
| 1 | 用户主动取消（不需要了） | 用户 |
| 2 | 信息填写错误（地址/电话） | 用户 |
| 3 | 重复下单 | 用户 |
| 4 | 超时未揽收 | 系统 |
| 5 | 违禁品/非法物品 | 网点 |
| 6 | 超区无法揽收 | 网点 |
| 7 | 其他 | 全部 |

原「超时未支付」已删除：寄付单未支付时快递员不会揽收，由「超时未揽收」统一兜底。原「收件人拒收」已删除：拒收只发生在 `4派送中`，取消流程不允许在该状态发起，语义由 `return_reason` 码 1 承载。码值已重排，本表尚未落库，无历史包袱。

## waybill_cancel

## 状态流转规则

| 状态 | 可跳转到 |
| --- | --- |
| 1 待揽收 | 2, 6, 7 |
| 2 已揽收 | 3, 6, 7 |
| 3 运输中 | 3, 4, 7, 8 |
| 4 派送中 | 4, 5, 7, 8 |
| 5 已签收 | 终态 |
| 6 已取消 | 终态 |
| 7 异常 | 3, 4, 6, 8 |
| 8 退回中 | 8, 9, 7 |
| 9 已退回 | 终态 |

三处自跳转：`3→3` 到达/离开转运中心、`4→4` 投递失败、`8→8` 退回途中过转运中心。均为状态不变但需留轨迹的事件。

`3→6` 不开放：运输中取消必须走 `3→8` 并写退回单，货的返程轨迹不能断。`7→6` 是否允许由最近一条 `waybill_exception.status_before` 决定，见上文异常规则。

进入 `5已签收` 的动作有三个：`6本人签收`、`11他人代收`、`12驿站签收`。三者结果状态相同，靠 `trace_action_id` 区分，不新增状态值。

进入 `7异常` 必须同时写一条 `waybill_exception`；进入 `8退回中` 必须同时写一条 `waybill_return`。轨迹与业务表在同一事务写入。
