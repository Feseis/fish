# 物流人员表草稿

状态：草稿（不长期维护）
用途：培训凭证、入职申请、物流人员、跨库 Outbox 四张表的结构讨论稿；`auth_user_profile` 已移至 `auth扩展草稿.md`，本文件不重复定义。定稿后分流至决策日志与待办。
更新时间：2026-11-09

## 已裁决口径

### 身份与资料

- 一切认证走 auth：`auth_account`（身份）+ `auth_user_profile`（资料）+ `auth_account_role`（权限）。
- 员工必定来自已注册账号，`logistics_staff.auth_account_id` 唯一。
- `auth_user_profile` 与 `auth_account` 1:1，`auth_account_id` 唯一；业务库只引用 `auth_account_id`，**不得引用 `auth_user_profile_id`**。表结构见 `auth扩展草稿.md`。
- 姓名三层口径：`auth_user_profile.real_name` 为权威；业务表当前态（`logistics_staff.staff_name`、`logistics_site.leader_name`）由 auth 的 `auth_outbox` 变更事件同步；历史凭证（`waybill_trace.operator_name` 等）永不更新。
- 人名字段统一 `VARCHAR(32)`；操作主体名称（可能是人名或网点名）统一 `VARCHAR(64)`。
- 码值列统一 `TINYINT UNSIGNED`。

### 培训与凭证

- 快递员经手贵重物品，入职前必须由网点组织培训，培训合格才发凭证。
- 凭证核验绑定 `auth_account_id`，不绑手机号；手机号只作联系用途，换号不影响已发凭证。
- 凭证一次性、有有效期、可追溯发证人。
- 归属网点由培训记录决定，申请时不选网点，也不人工分配。
- **培训登记前置校验**：服务端先确认 `auth_account` 存在且 `status=1`，否则拒绝登记；因此流程固定为「注册 → 培训 → 凭证 → 申请」。
- **登记留痕**：`issued_by_staff_id` 记谁录入，`created_at` 记何时录入，构成「培训记录由谁在何时建立」的凭证。
- **核销留痕**：`voucher_used_at` 记何时被用掉；申请单侧 `staff_training_id` 反向引用，形成「一凭证对应一次有效申请」的追溯链。核销账号不单列——核验条件强制 `trainee_auth_account_id = 申请人`，存两份是恒等冗余。
- **核销即定案**：核销成功即视为审核通过，一个凭证最多对应一条成功申请单；核验或建单任一步失败，整笔事务回滚，凭证保持未使用。不设驳回路径，也不设 `staff_apply.staff_training_id` 唯一键。
- 完整链路可追溯：账号 → 培训记录（网点、发证人、时间）→ 凭证核销（时间、账号）→ 申请单 → 审核 → 员工记录。

### 入职与审核

- App 自助申请当前**只开放快递员**（揽收+派送）；客服与卡车司机走其他渠道，暂不开放。
- 申请提交后系统同步核验凭证，核验通过即写 `approval(status=2)`，无人工待审窗口；并在同一事务建员工记录。核验失败直接返回错误，不建任何记录。
- 审核人抽象为系统：`audit_operator_type=1`、`audit_operator_id=NULL`；以后若要人工复核，只把 `operator_type` 改成 2，结构不变。
- 审核指针单向：业务表不存 `approval_id`，从 `approval` 按 `(biz_type=3, biz_id=staff_apply_id)` 反查。
- 通过时按账存在性分两路：无员工记录则 INSERT 并生成工号；已有记录则复用原行，置 `enabled=1`、复位 `hired_at`、清空 `left_at`、更新网点与岗位，工号不变。
- 离职不删行，置 `enabled=0` 并写 `left_at`；离职与账号状态无关，员工仍是正常 App 用户。
- 离职时撤销 `auth_account_role` 的 `auth_role_id=2`（物流员工）。
- 权限与岗位分工：所有员工在 auth 侧统一持有 `2 物流员工` 权限角色，岗位差异只由 `staff_role` 表达；`auth_role` 的「物流员工」是权限角色，不等于 `staff_role=1快递员`。

### 工号

- 格式：`岗位前缀` + `-` + 8 位全局流水，如 `KD-00000001`。
- 前缀：`KD` 快递员、`KF` 客服、`SJ` 司机；全局统一流水，不按前缀分段。
- 唯一且不回收；转岗不换号，前缀退化为「入职岗位」标记，当前岗位永远看 `staff_role`。
- 工号不编码网点，网点归属由 `logistics_site_id` 表达。
- 审核通过时生成，不在申请时预分配。

### 跨库一致性

- 业务库为权威，对 auth 的授权/撤权、对支付服务的退款请求都通过 Outbox 异步投递，最终一致，非实时。
- Outbox 与业务写入在同一本地事务；投递必须幂等。
- `target_service` 使用全库统一服务码：1认证 2物流 3支付 4短信。
- 不做枚举镜像表；业务库需要的外部码值（如 `auth_role_id`）用 Java 常量表达。
- 反向同步：auth 侧的姓名、手机号变更通过 `auth_outbox` 推送到物流服务，消费时按 `auth_account_id` 直接 UPDATE `logistics_staff`；姓名变更再按 `logistics_staff_id` 同步 `logistics_site.leader_name`。事件结构见 `auth扩展草稿.md`。

## logistics_staff

```sql
CREATE TABLE logistics_staff (
  logistics_staff_id CHAR(36)    NOT NULL COMMENT '人员主键 UUID；轨迹 operator_type=2 时作为 operator_id',
  auth_account_id    CHAR(36)    NOT NULL COMMENT '→ auth_account.auth_account_id；跨库只存值',
  staff_no           VARCHAR(16) NOT NULL COMMENT '工号：岗位前缀-8位全局流水，如 KD-00000001；唯一且不回收，转岗不改',
  staff_name         VARCHAR(32) NOT NULL COMMENT '姓名快照，入职时取自 auth_user_profile.real_name；由 auth_outbox 姓名变更事件同步',
  staff_phone        VARCHAR(20) NOT NULL COMMENT '手机号快照，入职时取自 auth_account.phone；由 auth_outbox 手机号变更事件同步',
  staff_role         TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '1快递员(揽收+派送) 2客服 3司机；当前实际只出现 1',
  logistics_site_id  CHAR(36)    NOT NULL COMMENT '归属网点 → logistics_site.logistics_site_id',

  enabled    TINYINT  NOT NULL DEFAULT 1 COMMENT '1在职 0离职；不删行，历史轨迹仍需渲染',
  hired_at   DATETIME NOT NULL COMMENT '当前雇佣段开始时间；重新入职时复位，历史见离职日志表',
  left_at    DATETIME NULL     COMMENT '离职时间；在职为 NULL，重新入职时清空',

  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (logistics_staff_id),
  UNIQUE KEY uk_auth_account (auth_account_id),
  UNIQUE KEY uk_staff_no (staff_no),
  KEY idx_site_role (logistics_site_id, staff_role)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='物流人员表';
```

## staff_training

```sql
CREATE TABLE staff_training (
  staff_training_id       CHAR(36)    NOT NULL COMMENT '培训记录主键 UUID',
  staff_role              TINYINT UNSIGNED NOT NULL COMMENT '凭证对应岗位：1快递员 2客服 3司机；无默认值，签发方必填',
  logistics_site_id       CHAR(36)    NOT NULL COMMENT '组织培训的网点 → logistics_site.logistics_site_id；也是入职后的归属网点',
  trainee_auth_account_id CHAR(36)    NOT NULL COMMENT '学员账号 → auth_account.auth_account_id；凭证核验依据',
  trainee_name            VARCHAR(32) NOT NULL COMMENT '姓名快照，发证时取自 auth_user_profile.real_name；由 auth_outbox 姓名变更事件同步',
  trainee_phone           VARCHAR(20) NULL     COMMENT '手机号快照，发证时取自 auth_account.phone',

  trained_at              DATETIME    NOT NULL COMMENT '培训完成时间',
  result                  TINYINT UNSIGNED NOT NULL COMMENT '1合格 2不合格',
  voucher_code            VARCHAR(32) NULL     COMMENT '培训凭证码，全局唯一；仅合格时生成，12 位字母数字',
  voucher_expire_at       DATETIME    NULL     COMMENT '凭证有效期；到期即失效，入职时置为当前时刻',
  issued_by_staff_id      CHAR(36)    NULL     COMMENT '发证人 → logistics_staff.logistics_staff_id；外部工具发证时为 NULL',
  issued_by_staff_name    VARCHAR(32) NULL     COMMENT '发证人姓名快照；外部工具发证时固定 System',

  created_at              DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at              DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (staff_training_id),
  UNIQUE KEY uk_voucher (voucher_code),
  UNIQUE KEY uk_account_role (trainee_auth_account_id, staff_role),
  KEY idx_site_time (logistics_site_id, trained_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='网点培训与凭证表';
```

核验条件：`voucher_code` 命中 + `voucher_expire_at > now()` + `trainee_auth_account_id = 申请人 auth_account_id` + `staff_role = apply_staff_role` + `result = 1`。不做核销：凭证只有「有效 / 失效」两种状态，入职成功后把 `voucher_expire_at` 置为当前时刻即失效。同一账号同一岗位只保留一条凭证，由 `uk_account_role` 保证；过期后重新激活的接口另行实现（见待办 `E-13`）。

## staff_apply

```sql
CREATE TABLE staff_apply (
  staff_apply_id    CHAR(36)     NOT NULL COMMENT '申请单主键 UUID',
  auth_account_id    CHAR(36)     NOT NULL COMMENT '申请人账号 → auth_account.auth_account_id',
  staff_training_id CHAR(36)     NOT NULL COMMENT '→ staff_training.staff_training_id；归属网点由培训记录决定',
  apply_staff_role  TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '申请岗位：当前只允许 1快递员(揽收+派送)；客服/司机预留',
  apply_remark      VARCHAR(255) NULL     COMMENT '申请人自述',

  created_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '申请时间',
  updated_at        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (staff_apply_id),
  KEY idx_account_time (auth_account_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='员工入职申请表';
```

审核关系不在此表存 `approval_id`，从 `approval` 侧按 `(biz_type=3, biz_id=staff_apply_id)` 反查。防重只靠凭证原子核销：同一凭证核销后不可再用，因此最多对应一条成功申请单。

核验、建单、建员工、写审核与事件在同一事务：校验有效期/归属账号/未核销/合格/账号 `status=1`/`real_name` 非空 → 原子核销凭证 → INSERT `staff_apply` → INSERT `approval(status=2)` → INSERT 或 UPDATE `logistics_staff` → INSERT `event_outbox`。任一环节失败整笔回滚，凭证保持未使用。

## event_outbox

```sql
CREATE TABLE event_outbox (
  event_outbox_id BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '事件主键，自增',
  target_service  TINYINT UNSIGNED NOT NULL COMMENT '目标服务：1认证 3支付；服务码全库统一',
  event_type      TINYINT UNSIGNED NOT NULL COMMENT '本表独立事件词表：1授予角色 2撤销角色 3业务终止（关单+退款）；不与 payment_outbox 共用',
  auth_account_id CHAR(36)         NULL     COMMENT '目标账号 → auth_account.auth_account_id；仅 auth 事件填写',
  auth_role_id    TINYINT UNSIGNED NULL     COMMENT '目标角色码，对应 auth_role.auth_role_id；仅 auth 事件填写',
  biz_type        TINYINT UNSIGNED NOT NULL COMMENT '来源业务（全库统一词表）：1运单 2运单取消单 3员工入职申请单 4员工离职',
  biz_id          CHAR(36)         NOT NULL COMMENT '来源业务主键：biz_type=1 为 waybill_id，2 为 waybill_cancel_id，3 为 staff_apply_id，4 为 logistics_staff_id',
  waybill_id      CHAR(36)         NULL     COMMENT '关联运单 → waybill.waybill_id；业务终止事件（event_type=3）必填，供支付服务按 waybill_id 定位运单支付单',
  status          TINYINT          NOT NULL DEFAULT 1 COMMENT '1待投递 2已投递 3待重试 4已放弃',
  retry_count     TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '已重试次数',
  next_retry_at   DATETIME         NULL     COMMENT '下次重试时间；待投递为 NULL',
  last_error      VARCHAR(255)     NULL     COMMENT '最近一次失败原因',
  created_at      DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (event_outbox_id),
  KEY idx_status_next (status, next_retry_at),
  KEY idx_biz (biz_type, biz_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='跨库事件投递表（Outbox）';
```

## 入职事务边界

申请提交即审核，一个本地事务内：

```
① 校验员工身份：该账号已有 logistics_staff 记录 → 409 ALREADY_STAFF
② 校验凭证：voucher_code 命中、result=1、voucher_expire_at > now()、trainee_auth_account_id=申请人
③ 生成工号：staff_seq 取号，KD- + 8 位全局流水
④ INSERT logistics_staff（姓名/手机号取凭证快照，岗位与网点取凭证）
⑤ INSERT staff_apply（apply_staff_role = 凭证岗位）
⑥ INSERT approval (biz_type=3, biz_id=staff_apply_id, status=2, audit_operator_type=1, audited_at=now())
⑦ UPDATE staff_training SET voucher_expire_at=now()，使用即失效
⑧ 同步调 auth 授予 role_id=2，失败整笔回滚
⑨ INSERT event_outbox (target_service=1, event_type=1, auth_role_id=2, biz_type=3, biz_id=staff_apply_id)
COMMIT
```

任一环节失败整笔回滚。没有待审状态，也没有驳回回滚：`approval.status` 只会出现 2，保留 1/3/4 是为通用表结构与未来人工复核留位。

角色授予以同步调用为准，`event_outbox` 仅作审计与后续补偿；`⑨` 在投递器实现前不会被消费。

离职同理：`event_type=2`，语义为撤销角色；`biz_type=4`、`biz_id=logistics_staff_id`，`auth_account_id` 与 `auth_role_id` 照填。
