# 短信表草稿

状态：草稿（不长期维护）
用途：短信服务表结构讨论稿；定稿后分流至决策日志与待办。
更新时间：2026-11-06

## 已裁决口径

- 短信服务独立微服务，库 `fish_sms`，所有微服务共用的基础设施。
- 服务间调用统一服务码：`1认证 2物流 3支付 4短信`；短信服务只做服务端，`source_service` 记录调用方。
- **文案进代码，不建模板表**：模板以枚举常量维护，改动必须发版并过代码评审，禁止在线修改。
- 渠道为 fish-pbox 的 `POST /sms/send-api`，`content` 为自由文本，由本服务渲染后传入。
- 幂等键 `request_id` 由调用方生成，重复请求撞唯一键时**返回已有记录的结果**（包括失败），不重复下发。失败后调用方要重试必须换新 `request_id`。
- 发送记录 append-only，只增不改。
- **敏感内容脱敏**：`LOGIN_CODE` 的验证码在落库前替换为 `******`；`PAY_REMIND` 的支付链接只保留域名与短码，不存完整 `pay_token`。

## 模板枚举

| 模板码 | messageType | 正文（含占位符） |
| --- | --- | --- |
| `LOGIN_CODE` | CODE | 验证码提醒：尊敬的用户，您正在使用验证码登录，验证码为 {1} |
| `PAY_REMIND` | NOTICE | 您的到付快件 {1} 应付 {2} 元，请在 {3} 前完成支付：{4} |
| `PAY_REMIND_FINAL` | NOTICE | 您的到付快件 {1} 应付 {2} 元，已逾期，请联系快递员处理 |
| `ARREARS_REMIND` | NOTICE | 您的快件 {1} 退回运费 {2} 元尚未支付，请及时结清：{3} |
| `ARRIVAL_NOTICE` | NOTICE | 您的快件 {1} 已到达 {2}，请及时领取 |

签名前缀 `【飞鱼速递】` 由代码统一拼接，不写入模板正文。

`PAY_REMIND_FINAL` 专用于第 6 次催付（第 48 小时）：此时 `expire_at` 已到，链接必然失效，因此不带链接。

`ARREARS_REMIND` 用于退回运费欠费的第 1/3/7 天催收，链接指向结清入口。

## sms_record

```sql
CREATE TABLE sms_record (
  sms_record_id   BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '发送记录主键，自增',
  request_id      CHAR(36)        NOT NULL COMMENT '调用方生成的幂等号，唯一',
  template_code   VARCHAR(32)     NOT NULL COMMENT '模板码，对应代码枚举，如 PAY_REMIND',
  target_phone    VARCHAR(20)     NOT NULL COMMENT '接收手机号',
  content         VARCHAR(600)    NOT NULL COMMENT '渲染后的完整文案（敏感内容已脱敏），发送时快照',
  source_service  TINYINT UNSIGNED NOT NULL COMMENT '调用方：1认证 2物流 3支付；服务码全库统一',
  biz_type        TINYINT UNSIGNED NULL COMMENT '业务类型，沿用全库统一词表；短信服务不解释',
  biz_id          CHAR(36)        NULL     COMMENT '调用方业务主键',
  result          TINYINT UNSIGNED NOT NULL COMMENT '1成功 2失败',
  fail_reason     VARCHAR(128)    NULL     COMMENT '失败原因，不含 apiCode',
  created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '发送时间，即时发送无需另设 sent_at',

  PRIMARY KEY (sms_record_id),
  UNIQUE KEY uk_request (request_id),
  KEY idx_phone_time (target_phone, created_at),
  KEY idx_biz (biz_type, biz_id),
  KEY idx_template_time (template_code, created_at),
  KEY idx_source_time (source_service, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='短信发送记录表（append-only）';
```

## 设计说明

- `template_code` 不是外键，只是码值，对应代码枚举 `SmsTemplate`；数据库不保存文案，避免线上被改。
- `content` 存渲染后的全文（敏感内容已脱敏），模板以后改版，历史记录仍能还原当时发了什么。
- `fail_reason` 只存业务可读原因，`apiCode` 等凭证类字段不入库、不入日志。
- `biz_type` 沿用全库统一词表，短信服务不解释，仅用于按业务反查；新业务先扩词表再使用，不另立同名列词表。
